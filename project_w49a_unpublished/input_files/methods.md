**Phase 0 — Archive audit and provenance tracing (Weeks 1–4)**

Before any analysis begins, you need to pin down exactly which archival datasets the 2024.1.00717.S proposal is referring to when it cites prior VLA 7 mm and ALMA 1.2 mm/H29α observations of W49N. This is not a formality — the entire thesis structure depends on what you find, so treat it as a graded milestone with a hard four-week deadline.

1. *VLA 7 mm continuum provenance.* Search the NRAO Science Data Archive (https://data.nrao.edu) for W49A/W49N pointings at Ka-band (~7 mm, ~43 GHz), filtering by PI names associated with this science case (De Pree, Wilner, Tobin) and by the coordinates of the known hypercompact HII sources (e.g., G, K3, other De Pree-catalogued components). Record every project code that returns a match, along with observation date, array configuration, and whether the archive serves calibrated visibilities, images, or raw data only.
2. *ALMA 1.2 mm / H29α provenance.* Repeat the same search in the ALMA Science Archive, restricting to Band 6 (~1.2 mm) observations covering the H29α rest frequency (~231.9 GHz) toward W49N. Cross-check candidate project codes against the De Pree et al. 2024 A&A paper (arXiv:2404.02250) reference list and data-availability statement, since that paper used a specific, already-published continuum dataset for the same region — confirm explicitly whether its dataset is the same one referenced in the 2024.1.00717.S proposal text or a different, earlier one. Do not conflate the two: your thesis must trace and use only the dataset(s) that supply the H29α line and/or 1.2 mm continuum cited as the "prior ambiguous" observations, not just any W49A data.
3. *Release status and product level.* For every candidate project code, check the archive's data-release date field and confirm public status. For ALMA, check the "Product" tab of each observation to see whether pipeline image cubes/continuum maps are directly downloadable, or only calibrated measurement sets (MS) are staged. For the VLA, check whether CASA-calibrated data or only raw data is available (older 7 mm data, depending on epoch, may predate the VLA pipeline and require you to confirm whether NRAO staff-calibrated products exist).
4. *Track assignment.* Based on steps 1–3, assign the thesis to one of three tracks:
   - **Track A** — image-level H29α cubes and continuum maps already exist for at least one catalogued HC HII source in both the VLA and ALMA datasets. Proceed to Phase 1 directly.
   - **Track B** — only calibrated MS are archived. Budget 1–2 weeks to image the specific source(s) yourself in CASA using `tclean`, applying the delivered calibration tables as-is (no self-calibration, no re-derivation of bandpass/gain solutions). Use standard `tclean` parameters (natural or briggs weighting with robust ~0.5, appropriate cell size set to ≥1/5 of the synthesized beam, imsize set to cover the source plus primary-beam correction region), then proceed to Phase 1 with the images you produced.
   - **Track C** — neither dataset yields usable calibrated image-ready products. Pivot to a fully archival reanalysis using only the flux densities, sizes, and velocity measurements already published in De Pree et al.'s figures and tables (digitized via a tool such as WebPlotDigitizer where necessary), and carry those measurements into the same Phase 1 model-comparison framework at the resolution/SNR those publications report.

Document the audit outcome (project codes, release dates, product levels, track decision) as a standalone section of the thesis — this is the "reproducibility ledger" a committee will ask about, and it is also what justifies, quantitatively, why the PI team proposed the Band 9 follow-up.

**Phase 1 — Kinematic extraction (Weeks 5–10)**

Working from whichever data product resulted from Phase 0:

1. *Continuum emission-measure profile.* From the 7 mm and/or 1.2 mm continuum maps, extract a radial or elongation-axis brightness-temperature profile across each target HC HII region using CASA's `imstat`/`imval` or a Python-based radial profile script (astropy + photutils apertures). Convert brightness temperature to emission measure under the optically-thin/partially-thick free-free assumptions given in De Pree et al., to reproduce and extend their opacity diagnostics.
2. *H29α position–velocity (PV) diagram.* From the ALMA H29α cube, define a slit along the position angle of the continuum elongation (or, for sources with no clear elongation, along at least two orthogonal position angles) using CASA's `impv` task. Extract the PV diagram and fit the line centroid velocity as a function of position with a Gaussian-per-channel or moment-based fit (e.g., `bettermoments` or a custom `scipy.optimize.curve_fit` routine), producing a velocity-vs-offset curve with associated uncertainties from the fit covariance and the cube's per-channel noise.
3. *Beam and noise characterization.* Record the synthesized beam (major/minor axis, PA) and per-channel RMS noise for both datasets — these become the fixed instrumental inputs for every model fit and for the Monte Carlo fallback in Phase 2.

**Phase 2 — Kinematic model comparison (Weeks 10–16)**

1. *Analytic templates.* Construct three simple, physically motivated PV/velocity-field templates as forward models, each parameterized minimally to stay tractable for one student in one semester:
   - *Rotating disk:* Keplerian or power-law rotation curve v(r) ∝ r^-p, projected through inclination i, producing the classic "spider diagram" PV signature.
   - *Expanding shell:* a thin or thick spherical shell with radial expansion velocity v_exp, projected along the line of sight, producing a characteristic ellipse/double-horn PV pattern.
   - *Bipolar/biconical outflow:* a conical velocity field with opening angle and inclination as free parameters, producing an asymmetric, spatially offset PV signature.
   Implement each template in Python as a function that takes (inclination, characteristic velocity, characteristic radius, position angle) and returns a synthetic PV diagram sampled on the same spatial/velocity grid as the data.
2. *Grid search and fitting.* For each template, grid-search or MCMC-sample (e.g., `emcee`) over inclination and the 2–3 physical parameters, convolving each synthetic PV diagram with the observed beam and channel width before comparison, and compute chi-square against the observed PV diagram (weighted by the per-channel noise from Phase 1).
3. *Model selection.* Compare the three best-fit templates using chi-square and AIC (and BIC as a cross-check, since AIC and BIC can disagree with few data points), correcting for the differing numbers of free parameters. Report which template is statistically preferred for each source and by how much (ΔAIC), together with corner plots of the fitted posteriors if MCMC was used.

**Phase 3 — Resolution/SNR fallback (as needed, Weeks 12–18, may run in parallel with Phase 2)**

If, once you have the real PV diagrams in hand, the beam covers only a few resolution elements across the source (check this explicitly by comparing the beam FWHM to the source angular size from the continuum map) — an outcome the proposal itself anticipates — do not force a verdict from underpowered data. Instead:

1. *Synthetic injection.* Using the same three analytic templates from Phase 2, generate synthetic H29α cubes at a grid of true model parameters, inject them at the actual observed beam size and per-channel noise (using CASA's `simobserve`/`simanalyze` or a lighter-weight Python beam-convolution + noise-injection script matched to the real observational setup), and re-extract PV diagrams exactly as done for the real data.
2. *Recovery test.* Run the same chi-square/AIC model-comparison pipeline from Phase 2 on the synthetic data, and determine, as a function of injected SNR and angular resolution (beam size relative to source size), the point at which the correct input model is recovered above a stated confidence threshold (e.g., ΔAIC > 10 in favor of the true model, in ≥90% of Monte Carlo trials).
3. *Deliverable.* Present this as a quantitative resolution/SNR requirements curve: "at the current beam and noise, disk vs. shell vs. outflow cannot be distinguished; discrimination at X% confidence requires resolution improved by factor Y and/or SNR improved by factor Z." This stands as a complete, self-contained result even if Phase 2 does not produce a confident verdict on the real data.

**Deliverables and tools**

Throughout, use CASA (imaging/PV extraction), Python (numpy/scipy/astropy/emcee/matplotlib) for model fitting and plotting, and the NRAO/ALMA archive interfaces for data provenance — no new observations, proposals, or proprietary data are used at any stage. The thesis document should present, per source: the continuum and H29α data used (with full provenance from Phase 0), the extracted PV diagram, the three-model comparison with statistical significance, and — where resolution-limited — the Monte Carlo requirements analysis quantifying what observational improvement would be needed to break the degeneracy.
